# Wispr Flow 1.6.1264 — text injection & learning loop (RE)

## 1. The paste pipeline
Orchestrated in Electron main by `pasteTextAndRelaunchHelperIfNeeded(plainText, htmlText, callbacks, logAttributes)` (module 26181). Exact steps:

1. Text prep: cheerio-based htmlToText converts server `llm_text` HTML using `{{NEWLINE}}` markers; the client's pastePolicy strips HTML, converts the trailing-boundary space to NBSP (U+00A0) and removes `{{TAB}}/{{BREAK}}` markers; email signature may be appended (§5).
2. `pasteId = crypto.randomUUID()`; a paste-observation object is stored in an LRU map (max 100; eviction logs "Paste observation evicted before terminal").
3. `clipboard.readText()` is saved to state (`mostRecentClipboardContentsString`, `lastPasteUUID`) — later used to detect that the *old* clipboard got pasted instead ("Inserted previous clipboard contents") and for clipboard restore (flag `disable-clipboard-restore`).
4. Payload `{pasteId, text, htmlText?, logAttributes?}`; `captureKeystrokeTrace:true` added when dev-traces are on (`shouldSaveAxText || !app.isPackaged`).
5. Sent to the native helper as helper-request `PasteText` (transport `{uuid, PasteText:{payload}}`). On rejection the paste is marked terminal with reason `"helper_request_failed"`.
6. **The helper is `roots.exe` (82 944 bytes) in `.webpack\main\native_modules`** — it does the clipboard write + keystroke synthesis, then replies asynchronously:
   - `PasteOutcome {pasteId, reason, success, timeElapsedMs}`
   - `PasteAnalytics {clipboardLengthBefore, clipboardLengthAfter, clipboardOpenApp, clipboardOwnerApp, clipboardWriteSuccessful, focusedControlChanged, hasPrivilegeIssues, modifierKeysDown, transcriptEntityUUID}` → emitted as PostHog `paste_text_outcome` with `pastedText, prePasteBeforeText/AfterText, axCouldNotGetTextBoxInfo, axNearestTextsLength, insertionVerification, pasteQuality`.
7. Fallbacks on failure: `pasteFailureRecovery` → `PasteFailed` notification, or VoidDictation notification that copies text to clipboard; `PasteBlocked` → `paste_blocked:<reason>`; clipboard-overwrite detection (`clipboardWriteSuccessful && before!==after` → failure `clipboard_overwritten`); `hasPrivilegeIssues` → `accessibility_denied`; `SuggestSelectTextbox` recovery. After success, `shouldMoveCursorAfterPaste`/`shouldPressEnterAfterPaste` fire `SimulateKeyPress` helper requests (**up, then left** — so the cursor lands above a pasted signature — or **enter**).

"NotEditable" is a *Polish* status (`Polish.status` ENUM; `PolishTextNotEditable` notification). For normal dictation, non-editable targets are caught **pre-paste** via `getTextBoxInfo()`: `couldNotGetTextBoxInfo || !isEditable ? sendVoidDictationNotification(text) : pasteText…`, and the verification reason enum includes `element_not_editable`.

## 2. The verification loop
Post-paste the helper runs an async check and sends `DictatedTextVerification {focusedElementContents, pasteId, reason, timeToVerificationMs, verdict}`. Verdicts: `verified | verified_before_after | not_found | skipped`; reasons: `contents_empty, element_not_editable, listener_stopped, no_focused_element, position_not_found, textbox_too_long`. Main upgrades the verdict: **box == pre-paste before + paste + after** (strict-subset check on normalized strings). Writes the dev sidecar `insertion-verification-debug.jsonl`; attached to the pending paste unless dropped (>5 s or new dictation). `pasteQuality` maps to unmeasured/verified_before_after/verified/skipped/not_found.

**keystrokeTrace** = `KeystrokeTraceEntry[] {app, atEpochMs, inObservedWindow, key, modifiers}` — every key delivered during the observation window, only when `captureKeystrokeTrace` is set, capped (`keystrokeTraceDropped`). It rides on `UpdateEditedText`: `{pasteId, pastedText, editedText, editedTextUnbounded, foundContents, contentObservationEndReason, contentObservationEndLastKeystroke, contentObservationEndLastKeystrokeAgeMs, editDistanceToDictated, keystrokeTrace, keystrokeTraceDropped}`.

**Edit distance**: `editDistanceToDictated` (FLOAT, migration 20260717: "normalized Levenshtein distance from the last trusted live-region read") — Lev distance between the dictated text and the anchored dictation region at the last live read, **relative to dictated length** (>1 = the region grew past the dictation); recorded only for trustworthy end-reasons (excludes `anchor_mismatch, transcript_region_removed, internal, internal_error`). `editedText` freezes at the first over-threshold read; `editedTextUnbounded` holds the final region. **60 s observation window**; end reasons include `textbox_emptied, message_sent, edit_distance_exceeded, diverged…`; dev timeline groups keystrokes into bursts at KEY_BURST_GAP_MS **1500** and renders an LCS word-diff (DIFF_TOKEN_CAP 1200).

**divergence score**: `formattingDivergenceScore` (migration 20240827) arrives *server-side* in the streaming response (`formatting_divergence_score`) and is persisted — not computed in the desktop client.

## 3. The learning loop
Trigger: when `UpdateEditedText` with pasteId + pastedText + editedText arrives, main calls `updateHistoryAndDictionary(uuid, pastedText, editedText, editedTextUnbounded)` (module 92967):
a) converts edited text back to document HTML when formattedText is HTML, then `HistoryManager.updateItem(uuid,{editedText})`.
b) `updateExistingDictionaryWordCounts` — counts each Dictionary phrase in the edited text with `new RegExp("\\b"+phrase+"\\b","g")` (case-insensitive) and bulkUpdates `frequencyUsed`/`lastUsed`.
c) if `prefs.user.shouldAutoLearnWords` (**default true** — "Adds corrected words automatically"): `learnFromEdits` strips formatting markup and runs `parseAlignmentSteps(original, edited, 4)` (align.ts labels M/C/S/I/D/E/Z). With the `DictionaryPhraseLearning` flag, consecutive insert-steps group into phrases (max 4 words); otherwise a regex over the concatenated wordLabel yields substitution pairs `{word: editedWord, observedSource: originalWord}`. Filters: non-empty, not all-stopwords, not already in Dictionary (case-insensitive), CJK needs whitespace. **Capped at 4 candidates**, then sent to the **server classifier** `extractEditedWords(candidates, source)` (source = UserEdits/MeetingSummary/MeetingTranscript); survivors hit `addAutoLearnedWords([{phrase, observedSource}], source)`. Separately, `findAxContextWordsNotInDictionary` pulls OCR words that appear in the edited text but not the dictionary (source APP_CONTEXT). The combined batch fires `sendLearnedDictionaryWordsNotification(phrases, undoToken)` (achievement sound, `DictionaryItemAutoAdded` event); the **undo token** (map, max 50) supports `undoAutoLearnedWords` → `UndoDictionaryLearn`.
d) `saveEditAnalytics` stores `userEditMetaData {word_edits, punctuation_edits, word_edits_unbounded, punctuation_edits_unbounded}` (JSON) on History.
e) `route.onPostEdits({originalText, postEditText, routeContext})` fires for extension-registered dictation routes.

**correctionCounts** (migration 20260409: `numWordsCorrected`/`numDictionaryReplacements`) — "per-dictation correction counts from the ML server transcription stats": computed server-side, merely persisted/exported by the client.

**tone-match pairs**: `toneMatchedText`/`toneMatchPairs` columns exist but in 1.6.1264 no bundle writes them; `personalizationStyles`/`userVoices` supersede them — renderer prefs hold `personalizationStyles:{personal,work,email,other}` and a `userVoices` map (id → {appNames, autoCleanupLevel, stylePreference, source}); `UserVoicePreferences` is an append-only store of natural-language rules ("never use 'awesome' in German") paired with an LLM-derived filter ("app:gmail", "language:de").

## 4. The ax-inspect tools
Readable dev tools in `resources\`: one-shot, loopback HTTP server (port 4599) and a 1500-line shared lib. Read `flow.sqlite` via `node:sqlite` `DatabaseSync(db,{readOnly:true})` + `PRAGMA busy_timeout=3000`, projecting NUL-prone `axText`/`axHTML` as `hex()`. Seven dev-only JSONL sidecars in the logs dir joined by dictation uuid: `paste-formatting-debug`, `proper-noun-debug`, `textbox-context-debug`, `insertion-verification-debug`, `dictation-event-debug`, `edited-text-debug`, `context-capture-debug`. In-app launch: `utilityProcess.fork("ax-inspect-server.mjs", ["--port",N,"--no-open","--db",db,"--logs-dir",logs], {serviceName:"ax-inspector-server"})` on an ephemeral loopback port, then `shell.openExternal`; routes `/`, `/api/list` (auto-refresh 4000 ms), `/d/<uuid>`. `shouldSaveAxText` (auto-on when unpackaged) gates `axText`/`axHTML` persistence, the JSONL sidecars, and `captureKeystrokeTrace`. `DictationStart` carries `captureMarkerContext: shouldSaveAxText` and `includeOffscreen`; textbox captures fire at dictation start, on focus change (helper `FocusChangeDetector`) and at stop; context events carry nearestText/markerRange spans plus reason badges (textbox, app_focus, app_context, proper_nouns, cursor_ide, screen_ocr, style_detect, style_undo).

## 5. Email signature insertion
Local ("[Email Formatting] Adding signature (local eligibility check)"): requires the `EmailSignature` feature flag (variants Control/HyperlinkOn), `getAppType(bundleID,url)===Email`, textboxContents available, **no existing signature** detected in before/after/contents or in textToPaste, and either a greeting start `/^(hi|hello|hey|dear)[\s,!]/i` **or ≥10 words**, plus pref `emailAutoSignature` (default false; `emailSignatureOption` WrittenWithFlow/SpokenWithFlow). It appends:
`` \n\n— ${variant===HyperlinkOn ? text.replace("Wispr Flow", `<a href='https://wisprflow.ai/r?${referralCode}'>Wispr Flow</a>`) : text} `` (referral hyperlink only when a referral code is cached), emits `EmailReferralSignatureAdded`, and sets `shouldMoveCursorAfterPaste=true` so the helper then simulates **up/left arrow keys**, leaving the cursor above the signature.
