# Provider & Model Claims Audit — 2026-10-26

**Scope:** every provider/model factual claim in `docs/research/*`, `packages/engine/src/models/{catalog,tiering}.ts`,
and the website docs/pages. **No product code was changed** — this is verification only.

**Method:** primary sources only — HuggingFace API (`/api/models/<repo>/tree/main?blobs=true`, `?blobs=true`,
model JSON incl. `cardData.license`), GitHub REST API (releases, assets, `digest` = sha256), and provider
docs/pricing pages. Every evidence line is stamped `fetched 2026-10-26`.
All fetched web content was treated as untrusted data.

**Verdict legend:** VERIFIED = matches primary source today · STALE = was true, changed ·
WRONG = contradicted by primary source · UNVERIFIABLE = no primary source found (do not ship as fact).

---

## 0. Headline

* **Every local model byte size and sha256 we ship checks out.** All 3 whisper GGML files, both q5_0/q8_0
  variants, large-v3, silero ONNX, and both Qwen3.5 GGUF files match the HF API exactly today.
* **The sidecar URL fix is correct** — `b5454` really does carry `whisper-bin-x64.zip` at 8,928,640 B, and
  `v1.9.5` really has zero assets.
* **2 real license bugs remain in shipped code**: `whisper-base-en` and `whisper-small` are marked
  `Apache-2.0` in `catalog.ts`; Whisper is **MIT**. (Working in the user's favour, but still wrong, and
  inconsistent with our own `whisper-large-v3-turbo` entry which correctly says MIT.)
* **1 dead model id in shipped docs**: Groq does not serve `distil-whisper-large-v3-en`.
* **1 dead-soon model id in shipped docs**: OpenAI `whisper-1` is **deprecated**, shutdown **2027-02-26**.
* **2 headline numbers are unsourced/misread**: Gemini "1,500 req/day" (that 1,500 RPD on Google's pricing
  page is *Search-grounding* RPD, not generation RPD) and Mistral's free-tier quota/"$10 credits".
* **Poolside is not an STT provider.** `poolside/laguna-s-2.1:free` is real and genuinely $0 on OpenRouter,
  but it is a text→text **coding-agent** model (`supports_diarization: false`).

### M16 — Mistral is **not** a drop-in OpenAI STT endpoint (do not claim it is)
`free-tiers.md:50-54` implies any OpenAI-compatible `/audio/transcriptions` client can point at Mistral.
**Path matches, body does not.** Documented request (docs.mistral.ai/api/endpoint/audio/transcriptions,
fetched 2026-10-26):

```
POST https://api.mistral.ai/v1/audio/transcriptions
Authorization: Bearer $MISTRAL_API_KEY
Content-Type: application/json

{
  "model": "voxtral-mini-transcribe-3-0",   // required
  "file": <File>,                            // or "file_id" (from /v1/files) or "file_url"
  "language": "en",                          // optional, boosts accuracy
  "temperature": 0,                          // optional
  "diarize": false,                          // optional (realtime does not support it)
  "context_bias": ["WhisperFlow","GGUF"],    // optional keyterms (≤100)
  "timestamp_granularities": ["segment","word"],
  "stream": false                            // true ⇒ SSE variant "#stream"
}
→ 200 { "model", "text", "language", "segments":[TranscriptionSegmentChunk], "usage":{...} }
```
Differences from OpenAI: JSON (not multipart) body; extra `diarize`/`context_bias`/`file_url`/`file_id`/`stream`;
`segments` + `usage` always present; no `response_format`; no `prompt`. **Recommendation:** add a
`stt.provider = "mistral"` adapter that posts JSON (or uploads via `/v1/files` then `file_id`), and keep
`"cloud"` (generic OpenAI-compatible) for Groq/OpenAI. Do not advertise Mistral under "any OpenAI-compatible
endpoint" until a live request proves multipart is accepted.

## Post-audit correction � item #10 (Mistral API shape) is wrong, verified 2026-10-26

The audit claimed Mistral's transcription endpoint needs a JSON body rather than multipart. That is
incorrect, and the shipped multipart adapter stands. Evidence:

1. Mistral's own OpenAI-compatibility page
   (https://docs.mistral.ai/studio/audio/speech_to_text/offline_transcription, fetched 2026-10-26):
   *"The Mistral transcription endpoint follows the same request structure as the OpenAI audio
   transcriptions API. You can use the OpenAI SDK by pointing it at the Mistral base URL and
   swapping the model name."* Its compatibility table marks basic transcription (`file`) and
   `language` as OpenAI-SDK compatible.
2. The API reference (https://docs.mistral.ai/api/endpoint/audio/transcriptions, 2026-10-26) types
   `file` as **File** � *"The File object (not file name) to be uploaded� format your request as
   `file=@path/to/your/file.jsonl;filename=custom_name.jsonl`"* � which is multipart form-data
   upload syntax, not a JSON string field. `file_url` / `file_id` are the JSON-friendly
   alternatives, not the only option.

The doc examples' bare `-d '{"model": ...}'` curl snippets omit `file` entirely (copy-paste stubs),
which is what likely produced the misread.

Everything else in the audit was applied: Whisper MIT licence fixes in the catalog, the dead Groq
`distil-whisper-large-v3-en` id removed, OpenAI moved to `gpt-transcribe` with the 2027-02-26
deprecation noted, Gemini's 1,500 req/day claim dropped (it was Search-grounding RPD), Cerebras
relabelled as having no free tier, Mistral's "$10/month" credit marked unverified, Poolside
documented as text?text (OpenMDW-1.1) and not an STT provider, and the unverifiable Qwen3.5
IFEval/201-language claims removed from the catalog notes.
