# WhisperFlow — v0.1.54 "Vocabulary Biasing"

## Names decode right the first time
The competitive-research P0a ships: **the personal dictionary now rides the
whisper.cpp decode prompt**. Where v0.1.53 waited for post-hoc fuzzy
correction (or the polish LLM) to fix "wishperflow" → "WhisperFlow", the
terms now bias the decoder itself:

```
Terms the speaker uses, spelled exactly: WhisperFlow, Parakeet, GigaAM.
<rolling transcript tail — last 220 chars>
```

This is the pattern Hex proved locally (its vocabulary list feeds
Whisper/Qwen3-ASR at decode). Zero extra passes, zero cloud — the preamble
is capped at 400 chars so a huge dictionary can't eat the context window,
deduped case-insensitively, keeping the dictionary's canonical casing.

- **`buildSttPrompt()`** (`packages/engine/src/text/sttPrompt.ts`) replaces
  the bare `raw.slice(-220)` in `DictationSession` — one function, pure,
  8/8 unit tests covering preamble/tail/budget/dedupe/disabled paths.
- **`stt.vocabularyBiasing`** config knob (default **on**) + a toggle on
  Dictation → Audio, beside language detection: "Your dictionary words
  ride the transcription prompt, so names decode right the first time —
  no cloud, no extra pass."
- **`WF_STT_ECHO_PROMPT`** test affordance on the mock STT adapter —
  smoke runs can now assert exactly what the decoder was told.

## Research note
Session 20's competitive research (Wispr Flow vs Hex, delivered earlier
today) recommended this as the cheapest accuracy win on the board — the
engine already observed corrections through edit-learning; initial-prompt
biasing is a whisper.cpp feature, not a new dependency. P0b (streaming
interim text) turned out to be **already built** in the session engine
(interim transcription every ~1.2 s broadcast as the live partial) — the
research gap analysis was conservative there.
